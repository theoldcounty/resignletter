Yes — what you’re describing is essentially a reusable “Promo Video Prompt Library”: a catalog of generic production prompts that you can feed into Replit alongside the app/project, screenshots, logos, copy, etc., and have it infer the actual product and generate a tailored promo.

The important part is to make the prompts product-agnostic but production-specific: tell Replit how to tell the story, what visual language to use, what evidence it can and cannot invent, and how to turn the actual app into the content.

The master prompt

This is the one I’d actually keep as your base Replit prompt.

MASTER PROMPT — GENERIC PRODUCT PROMO VIDEO GENERATOR

You are an expert creative director, motion designer, UX demonstrator, product marketer and frontend engineer.

Your task is to inspect the application you have been given and create a polished promotional video/showreel that explains:

1. What problem the product solves.
2. Who experiences that problem.
3. Why the problem matters.
4. How the application solves it.
5. How the user interacts with the application.
6. What the user gets as an output.
7. What the practical benefits are.
8. Why the product is worth using.
9. What makes the product distinctive.
10. What action the viewer should take next.

Do NOT invent product capabilities, statistics, testimonials, customers, revenue figures, performance claims or other factual information that cannot be verified from the application, supplied materials or explicitly provided content.

Where numerical evidence is unavailable, communicate the concept visually rather than inventing statistics.

For example:

* Use animated quantities only when they represent real data.
* Use relative visual metaphors instead of fabricated percentages.
* Use real application outputs wherever possible.
* Use clearly labelled illustrative graphics when demonstrating hypothetical scenarios.

INPUTS

Inspect all available project materials, including:

* Application UI
* Screenshots
* Existing branding
* Logo
* Colours
* Typography
* Copy
* Documentation
* Example outputs
* Data structures
* User flows
* Features
* Navigation
* Existing animations
* Existing assets

Infer the application’s core purpose from the actual project rather than requiring the developer to manually describe it.

If screenshots or assets are supplied, incorporate them naturally into the video.

⸻

CREATIVE STRUCTURE

Build the video as a sequence of cinematic scenes.

Default structure:

SCENE 01 — HOOK
Immediately establish the problem, curiosity or emotional tension.

SCENE 02 — THE PROBLEM
Show the frustrating, inefficient, expensive, confusing or time-consuming experience that exists without the product.

SCENE 03 — TRANSITION
Introduce the product as the change in the story.

SCENE 04 — THE PRODUCT
Reveal the actual application with polished motion graphics.

SCENE 05 — HOW IT WORKS
Demonstrate the primary workflow using the real interface.

SCENE 06 — TRANSFORMATION
Show the journey from input → processing → useful output.

SCENE 07 — BENEFITS
Visualise the practical benefits without fabricating unsupported claims.

SCENE 08 — DIFFERENTIATION
Show what makes this product interesting, distinctive or useful.

SCENE 09 — PROOF
Use real outputs, real UI, real data or supplied evidence wherever available.

SCENE 10 — CALL TO ACTION
End with a clear, memorable invitation to try, explore, upload, analyse, create, subscribe or otherwise use the product.

⸻

VISUAL LANGUAGE

Create a sophisticated mixture of:

* Motion graphics
* UI animation
* Parallax
* Layered interfaces
* Animated typography
* Charts
* Graphs
* Progress indicators
* Data visualisations
* Cards
* Carousels
* Zoom transitions
* Device mockups
* Document transformations
* Before/after comparisons
* Cursor interactions
* Highlight effects
* Cinematic camera movement
* Depth and perspective
* Particle/light effects where appropriate
* Subtle 3D effects
* Brand-consistent transitions

The result should feel like a professionally produced technology/product advertisement rather than a slideshow.

Do not overload every scene with effects.

Use visual hierarchy:
HOOK → PROBLEM → PRODUCT → TRANSFORMATION → BENEFITS → PROOF → CTA.

⸻

BRANDING

Extract the visual identity of the application from the supplied project.

Use:

* Existing brand colours
* Existing logo
* Existing typography
* Existing UI components
* Existing iconography

If no formal brand system exists, create a restrained visual identity based on the application’s existing interface.

Maintain visual consistency throughout the video.

Do not introduce unrelated branding.

⸻

DATA VISUALISATION RULES

Use charts and graphs when they genuinely help explain the product.

Possible visualisations include:

* Bar charts
* Line charts
* Donut charts
* Timelines
* Flow diagrams
* Comparison tables
* Progress indicators
* Heatmaps
* Network diagrams
* Before/after metrics
* Process funnels
* Information density visualisations

IMPORTANT:

Never fabricate statistics.

If the application does not contain numerical evidence, do not create fake percentages such as:

“73% faster”

“10x more productive”

“92% of users”

Instead use:

* qualitative comparisons
* actual supplied data
* illustrative labels
* visual transformations
* process reduction
* real screenshots
* clearly marked hypothetical examples

⸻

UI PRESENTATION

Treat the application’s interface as a major visual asset.

Use cinematic UI demonstrations such as:

* zooming into important interface elements
* highlighting controls
* cursor movement
* animated clicks
* expanding cards
* scrolling through results
* filtering data
* opening documents
* transforming inputs into outputs
* switching views
* carousel transitions
* layered UI panels
* perspective/parallax
* screen-to-screen transitions

Avoid simply recording a static screen.

Make the interface feel alive.

⸻

STORYTELLING

The viewer should understand the product without needing prior knowledge.

Every scene should answer at least one of these questions:

“What is the problem?”

“Why should I care?”

“What does this product do?”

“How does it work?”

“What do I get?”

“Why is that useful?”

“What should I do next?”

Use short, confident copy.

Prefer:

“Upload.”

“Analyse.”

“Understand.”

“Act.”

over:

“Our revolutionary AI-powered platform enables users to…”

⸻

AUDIO

Select an audio direction appropriate to the chosen creative style.

Possible approaches:

* Synthwave
* Retro electronic
* Cinematic
* Minimal technology
* Corporate-modern
* Documentary
* Percussive
* Ambient
* Playful
* Comedy/informercial

Synchronise major visual transitions with the rhythm.

Use subtle sound design:

* clicks
* UI sounds
* VHS noise
* tape hiss
* transitions
* notification sounds
* keyboard sounds
* digital glitches
* impact sounds

Do not make the soundtrack overpower the product explanation.

OUTPUT FORMAT

Design the video as a reusable production sequence.

For every scene define:

SCENE NUMBER
PURPOSE
DURATION
VISUAL
ON-SCREEN TEXT
UI ELEMENTS
ANIMATION
TRANSITION

DATA USED
WHY THE SCENE EXISTS

Aim for approximately 30–90 seconds unless the application requires another duration.

Also provide alternative cuts where appropriate:

15-second social version
30-second promotional version
60-second explainer
90-second website/showreel version

⸻

IMPORTANT CREATIVE PRINCIPLE

Do not merely describe the application.

SELL THE EXPERIENCE OF USING IT.

The viewer should feel the contrast between:

BEFORE → AFTER

CONFUSION → CLARITY

EFFORT → SIMPLICITY

RAW INFORMATION → USEFUL INFORMATION

PROBLEM → SOLUTION

STATIC DOCUMENT → ACTIONABLE OUTPUT

MANUAL WORK → ASSISTED WORK

Use whichever contrast genuinely applies to the application.

Do not force a contrast that the product does not support.

⸻

FINAL QUALITY STANDARD

The finished concept should feel like:

* a premium SaaS product launch
* a technology commercial
* a polished startup showreel
* a cinematic UI demonstration
* a social-media-ready product advertisement

rather than:

* a PowerPoint presentation
* a generic AI-generated commercial
* a collection of screenshots
* a fake statistics presentation
* a feature checklist

Prioritise clarity, visual storytelling, authenticity, strong pacing and real evidence.

That becomes your master template.

Then you can prepend something like:

Use P01 — RetroWave

or

Use P07 — The £1 Argument

and Replit knows what creative treatment to apply.

Your actual prompt catalog

P01 — RETROWAVE

Use for: attention, launch videos, social, brand personality.

Creative direction: VHS / 1980s–90s technology commercial / synthwave / CRT / cassette aesthetic.

Create the promotional video using a deliberately nostalgic 1980s/1990s retro-futuristic aesthetic.

Open with a VHS/CRT television effect:

* tracking distortion
* scanlines
* tape noise
* chromatic aberration
* brief static
* cassette loading effect
* timestamp-style graphics
* degraded broadcast quality

Begin as though the viewer has discovered an old television commercial from the future.

Gradually transition from deliberately low-fidelity VHS imagery into the application’s crisp modern interface.

Create an intentional visual contrast:

OLD WAY → NEW WAY

Use synthwave/electronic-inspired music and rhythmic transitions.

Use neon-inspired lighting only where compatible with the application’s branding.

Once the product is introduced, progressively reduce the VHS distortion and allow the modern application UI to become increasingly clean and sharp.

The final scene should be completely modern and polished, implying that the product has moved the viewer from an outdated way of working into a modern workflow.

Use real application UI and real product functionality.

Do not invent statistics.

The retro aesthetic should frame the story, not obscure the product.

This one sounds particularly relevant to what you’re building.

Have Replit inspect the application’s actual data and turn it into a visual story.

Create a premium data-driven promotional sequence.

Begin with raw information entering the system.

Gradually transform it through:

RAW DATA
↓
PROCESSING
↓
STRUCTURE
↓
PATTERNS
↓
INSIGHT
↓
ACTION

Use animated charts, graphs, cards, timelines, tables, filters and visual relationships where supported by the actual application.

Use real data wherever available.

Never fabricate numbers.

If insufficient numerical data exists, use abstract visual representations of information rather than invented statistics.

Animate charts progressively so the viewer understands what is changing and why.

Use camera movement and parallax to create depth.

Move between high-level visualisations and detailed UI views.

The sequence should communicate that the product turns information into something easier to understand and use.

Finish by returning to the real application interface and showing the user what they can actually do with the resulting information.

The “don’t make stuff up” prompt

I’d actually put this into every single one of your templates:

PROMOTIONAL ACCURACY RULES

Use the actual application as the source of truth.

Never invent:

* statistics
* percentages
* customer numbers
* testimonials
* revenue
* savings
* performance improvements
* market share
* user counts
* scientific claims
* customer logos
* awards
* certifications
* integrations
* features
* capabilities

unless they are explicitly present in the supplied project or source material.

If a marketing claim cannot be verified, replace it with a visual demonstration.

Instead of:

“50% faster”

show the actual workflow.

Instead of:

“10x more productive”

show the transformation from a complex process into a simpler workflow.

Instead of:

“Trusted by thousands”

show the actual product and its outputs.

When statistics are available, identify their source and context.

When demonstrating hypothetical scenarios, make it clear that they are illustrative.

The goal is to make the product look compelling through its actual capabilities rather than fabricated claims.
